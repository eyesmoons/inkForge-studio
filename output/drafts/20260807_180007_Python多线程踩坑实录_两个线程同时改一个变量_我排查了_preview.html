Python多线程踩坑实录：两个线程同时改一个变量，我排查了两天

先问你一个问题：你写过多线程程序吗？

如果写过，大概率遇到过这种情况——程序跑起来没问题，数据也对。但只要数据量一大，或者并发一高，结果就开始出错。而且这种错还特别难查，不是每次都错，是偶尔错，看运气。

我当年第一次遇到这个，排查了整整两天。代码翻来覆去看了无数遍，逻辑上完全没问题。最后才意识到，问题出在三个线程同时改一个变量上。

这就是今天要聊的核心：线程安全。

什么是线程

先说基础概念。

线程是操作系统进行任务调度与CPU执行的最小单位。注意，是最小单位。一个进程里面可以跑多个线程，而同一进程内所有线程能够共享进程中的资源。

这句话是理解多线程一切问题的根源。

想一下：多个线程共享同一份资源，意味着什么？意味着它们可以同时读写同一个变量。那如果其中一个线程正在写，另一个线程也在写，会发生什么？

数据错乱。

这就是线程安全问题的本质。多线程代表在同一个进程内部并发执行多项任务，而这个"并发"带来的，不光是效率提升，还有数据竞争的风险。

创建线程的两种方式

Python里面创建线程，主流有两种做法。

方式一：使用threading.Thread

这是最基础的方式。先看构造参数：

threading.Thread(group=None, target=None, name=None, args=(), kwargs={}, *, daemon=None)

每个参数都有讲究。group目前固定为None，是给未来扩展预留的。target是你线程要执行的函数，不传就什么都不干。name可以自定义，不传系统会按Thread-N的格式自动生成。args和kwargs是给目标函数传参用的，前者传元组，后者传字典。daemon设置是否为守护线程，默认继承当前线程的守护属性。

线程对象有几个常用属性和方法，写代码的时候用得上：

name获取线程名，daemon查看守护标识，ident获取内部标识，native_id获取操作系统分配的原生ID。

方法方面，start()启动线程，run()定义执行逻辑，join()阻塞主线程等子线程跑完，is_alive()判断线程是否在运行。

另外还有两个工具函数：threading.enumerate()获取所有存活线程列表，threading.current_thread()获取当前线程对象。

看个实际例子，两条线程分别循环输出不同内容：

import time
import threading

def loop_print(content):
    while True:
        print(f"{threading.current_thread().name}：{content}")
        time.sleep(0.6)

if __name__ == "__main__":
    t1 = threading.Thread(target=loop_print, name="线程A", args=["学习Python"])
    t2 = threading.Thread(target=loop_print, name="线程B", args=["掌握并发编程"])
    t1.start()
    t2.start()

方式二：自定义Thread子类

如果你想封装可复用的线程逻辑，继承threading.Thread重写run()方法更合适。

import time
import threading

class TaskThread(threading.Thread):
    def __init__(self, name, msg):
        super().__init__()
        self.name = name
        self.msg = msg

    def run(self):
        while True:
            print(f"{self.name} -> {self.msg}")
            time.sleep(0.3)

if __name__ == "__main__":
    TaskThread("线程A", "处理数据1").start()
    TaskThread("线程B", "处理数据2").start()

这种方式的好处是，线程的逻辑可以封装成类，复用性更强。

线程池：批量管理线程

线程创建和销毁是有开销的。如果任务量很大，频繁创建销毁线程会浪费不少资源。这时候就需要线程池。

ThreadPoolExecutor位于concurrent.futures模块，统一管理线程，批量分发任务，还能方便地获取任务返回值。

创建参数如下：

concurrent.futures.ThreadPoolExecutor(max_workers=None, thread_name_prefix="", initializer=None, initargs=())

max_workers是最大并发线程数，不填就自动适配系统资源。thread_name_prefix给池内线程统一加前缀。initializer和initargs是线程启动时执行的初始化函数及其参数。

常用方法有三个：

submit(fn, *args, **kwargs)提交单个任务，返回Future对象，用.result()拿返回值。map(func, *iterables)类似内置map，并行遍历可迭代对象执行任务。shutdown(wait=True, cancel_futures=False)关闭线程池，wait控制是否等任务完成，cancel_futures选择是否取消排队中的任务。

强烈推荐搭配with上下文管理器用，自动释放线程资源，省心。

看个批量计算平方的例子：

import concurrent.futures

def calc_square(num):
    res = num ** 2
    print(f"线程计算：{num} 的平方 = {res}")
    return res

if __name__ == "__main__":
    nums = [2, 4, 6, 8, 10]
    with concurrent.futures.ThreadPoolExecutor(max_workers=3) as executor:
        futures = [executor.submit(calc_square, n) for n in nums]

线程安全问题：多线程的坑

前面说的都是怎么创建线程。现在聊真正重要的东西——线程安全。

同一进程下多线程共享全局变量，这本身没什么问题。问题出在多个线程同时修改同一个变量的时候。

我给你写一个场景：3个线程循环对同一个全局变量累加10次。

先看不加延时的版本：

import time
import threading

def add_count():
    global counter
    for _ in range(10):
        temp = counter + 1
        # time.sleep(0.01)
        counter = temp
        print(f"{threading.current_thread().name} : {counter}")

if __name__ == "__main__":
    counter = 0
    thread_list = [threading.Thread(target=add_count, name=f"线程{i}") for i in range(3)]
    [t.start() for t in thread_list]
    [t.join() for t in thread_list]
    print("最终数值：", counter)

因为运算速度极快，线程基本不会被中断，大概率输出正确结果——30。

但你把sleep那行注释去掉，加上time.sleep(0.01)，结果就开始出错了。

import time
import threading

def add_count():
    global counter
    for _ in range(10):
        temp = counter + 1
        time.sleep(0.01)
        counter = temp
        print(f"{threading.current_thread().name} : {counter}")

if __name__ == "__main__":
    counter = 0
    thread_list = [threading.Thread(target=add_count, name=f"线程{i}") for i in range(3)]
    [t.start() for t in thread_list]
    [t.join() for t in thread_list]
    print("最终数值：", counter)

最终数值不再是30，而是20、21、22之类的数字。

为什么？

因为加了延时之后，线程执行到counter = temp这行之前，可能会被中断。另一个线程趁机也读取了旧的counter值，各自加1，然后写回去。两个线程都写了同一个值，等于白加了一次。

这就是线程安全问题的典型场景。多个线程同时操作共享变量，互相覆盖对方的写入结果。

互斥锁：解决线程安全的方案

怎么解决？用互斥锁。

互斥锁的概念很直白：线程修改共享数据之前，先获取锁。资源上锁期间，其他线程无法操作，只能等着。当前线程处理完毕释放锁，其他线程才有机会抢占。

互斥锁保证同一时刻仅有一条线程操作共享资源，从而保障数据运算的准确性。

用Python的threading.Lock()创建锁实例，核心方法就两个：

lock.acquire()获取锁，lock.release()释放锁。

把累加的例子加上锁：

import time
import threading

lock = threading.Lock()
counter = 0

def add_count():
    global counter
    for _ in range(10):
        lock.acquire()
        temp = counter + 1
        time.sleep(0.01)
        counter = temp
        lock.release()
        print(f"{threading.current_thread().name} : {counter}")

if __name__ == "__main__":
    thread_list = [threading.Thread(target=add_count, name=f"线程{i}") for i in range(3)]
    [t.start() for t in thread_list]
    [t.join() for t in thread_list]
    print("最终数值：", counter)

这次不管跑多少次，最终数值都是30。

锁的机制就是，一个线程拿到锁之后，其他线程的acquire()会阻塞，直到锁被释放。这样就保证了对共享变量的操作是原子性的——要么不做，要么一口气做完。

不过用锁也要小心。acquire()之后一定要记得release()，否则其他线程会永远等下去。更推荐用with语句：

with lock:
    temp = counter + 1
    time.sleep(0.01)
    counter = temp

这样即使中间出异常，锁也会自动释放。

写在最后

多线程编程的核心问题，从来不是怎么创建线程，而是怎么保证数据安全。

线程是操作系统调度和CPU执行的最小单位，同一进程内的线程共享进程资源。这个"共享"既是多线程的优势，也是多线程的隐患。

当你写的程序涉及多个线程同时修改同一个变量时，一定要问自己一个问题：这里会不会有数据竞争？

如果有，加锁。

别觉得加锁影响性能。数据错了，性能再好也没用。

多线程的并发能力是把双刃剑，用好了效率翻倍，用不好数据全废。
