# DeepSeek V4 来了：1.6T参数开源，百万上下文，这是要逼死谁？

2026年4月29日，一个普通周三的早晨，DeepSeek 扔出了一颗炸弹。

不是预告，不是画饼，是直接发布。**DeepSeek V4**，1.6万亿参数，原生支持百万级上下文，开源自研，明确表态和华为芯片绑定。从参数到上下文到芯片选择，每一步都踩在行业最敏感的那根神经上。

更让人头皮发麻的是，他们还顺手发了一个通知：三个月后，现有的 deepseek-chat 和 deepseek-reasoner 接口要停用，所有人迁移到 V4-Flash。没有缓冲，没有商量，就是“新版本来了，旧的不留”。

你可能会问，1.6T 参数，百万上下文，这数字到底意味着什么？别急，我们一个一个拆。

## 参数堆到1.6T，不是炫技，是硬刚

先说参数。1.6T，也就是一万六千亿。这个数字放在一年前，是所有人不敢想的。GPT-4 的参数规模至今没有官方公布，业内猜测在1.8T左右。Claude 3.5 的参数更低调，估算在几百B。而 DeepSeek V4 直接扔出一个开源模型，参数规模直奔行业天花板。

很多人对参数有误解，觉得越大越慢，越大越笨。其实不然。**参数是模型的肌肉，上下文是模型的记忆力，而架构是模型的骨架。** DeepSeek V4 用的是 MoE，也就是混合专家模型。简单说，就是把一万多亿的参数分成很多个“专家模块”，每次推理只激活其中一小部分。你问一个问题，模型会判断这个问题该交给哪些专家处理，然后只调用这些专家的参数。

好处是什么？效率。1.6T 参数的模型，实际推理时可能只激活一两百亿参数。你享受到的是超大模型的智能水平，付出的计算成本和一个小模型差不多。这就是 MoE 的魅力——**用最少的钱，买到最大的脑袋。**

但问题是，MoE 模型不好训，更不好部署。专家模块之间的协调、负载均衡、通信开销，哪一个处理不好都会翻车。DeepSeek 能做到 1.6T 参数级别并稳定开源，说明他们在工程上确实下了血本。

有人会说，参数堆到这么大，有什么实际意义？我给你一个场景。你用 V4 写一个超长的技术方案，它不仅能理解你前面的逻辑，还能在50页之后准确引用你在第3页写的一个技术参数。不需要你反复强调“我之前说过”，不需要你手动粘贴上下文。**它记得，它理解，它还在乎。** 这就是超大参数带来的真实体验。

## 百万上下文，不是噱头，是洗牌

再看上下文长度。百万 token，也就是大约75万到80万个汉字。什么概念？一部《三体》三部曲一共约90万字。也就是说，你可以把整部《三体》喂给 V4，然后问它“罗辑在第二部第几章提出了黑暗森林法则”，它能在几秒内给你答案。不是靠搜索，不是靠摘要，而是真正理解过。

这不是简单的“记忆容量变大”。百万 token 意味着模型有能力处理整个项目文档、整本书籍、整段代码仓库。以前你写代码要分模块提问，现在你可以直接把整个项目丢进去，问它“这个函数在哪里被调用了”“这个模块的测试覆盖率是多少”。以前你写论文要分段润色，现在你可以把整篇论文丢进去，说“检查一下第5章和引言在论证逻辑上有没有矛盾”。

**真正可怕的是，百万上下文会成为行业标配。** 不是只有 DeepSeek 有，而是所有主流模型都会跟上。Google 的 Gemini 已经支持百万 token，Claude 也宣称在做长上下文。但 DeepSeek 是第一个把百万上下文做成开源模型的。这意味着什么？意味着创业公司不需要花巨资买 API，就能在自己的服务器上跑一个百万上下文的模型。这是一个巨大的降维打击。

当然，百万上下文不是没有代价。长上下文推理的显存消耗是指数级增长的。你本地跑一个7B模型，上下文从8K扩展到128K，显存消耗可能翻三四倍。所以 DeepSeek 说“百万上下文成标配”，其实潜台词是：**你的显卡准备好了吗？**

## 停用旧接口，不给你拖延的机会

这篇公告里最硬核的部分，不是参数，不是上下文，而是那三个字：停用了。

deepseek-chat 和 deepseek-reasoner 将在三个月后彻底下架。所有依赖这两个接口的应用，必须在90天内完成迁移。这对个人开发者来说影响不大，改个 model 参数就行。但对生产环境的用户来说，是一个不小的工程。你需要重新测试、重新调优、重新发布。如果有多个应用依赖 DeepSeek 的接口，这三个月会非常忙。

为什么 DeepSeek 要这么做？**因为他们不想养懒汉。** 很多开发者用着旧接口，嘴上说支持国产大模型，实际上连模型升级都不愿意做。DeepSeek 的态度很明确：我给了你三个月，够长了。你不上车，那是你的问题。

另一个角度看，这也说明 DeepSeek 对 V4 非常有信心。他们不怕用户流失，不怕用户因为迁移麻烦而转投其他模型。他们相信 V4 的能力足以让用户心甘情愿地迁移。这是一种自信，也是一种压迫感——你不跟上，就等着被淘汰。

更值得玩味的是，DeepSeek 在这个时间点宣布与华为芯片合作。**这不是一个技术选择，这是一个战略表态。** 在中美科技博弈的大背景下，DeepSeek 选择站队国产芯片，而且是华为的昇腾系列。这意味着 DeepSeek V4 的推理和训练可以完全跑在国产硬件上。这对国内的企业用户来说，是一个巨大的吸引力。不用再担心制裁，不用再担心断供，所有东西都跑在国内的服务器上。

你说这是爱国营销也好，是商业策略也好，结果就是：**DeepSeek 给自己建了一堵墙，别人进不来，自己出不去，但墙里的人很安全。**

## 写在最后

DeepSeek V4 的发布，让我想起一句话：**最好的反超，不是追上对手，而是重新定义赛道。** 当别人还在比参数、比上下文、比芯片选择，DeepSeek 已经把这些全做了，而且做成了开源。你不需要猜它怎么实现的，代码就在那里，自己去读。

对开发者来说，这是一个幸福的烦恼。幸福的是，你有一个免费、开源、百万上下文、1.6T参数的大模型可以用。烦恼的是，你得在三周内改代码。

对行业来说，这是一个分水岭。百万上下文不再是小众需求，不再是大厂专利。开源模型第一次在核心指标上追平甚至超越了闭源模型。这是2026年大模型领域最值得记录的一刻。

最后，用一句话总结我对 DeepSeek V4 的看法：**它不是来抢市场的，它是来重新洗牌的。** 洗完之后，留下的只有两种人——跟上的人，和还在改代码的人。

从实践中来，到系统中去。
