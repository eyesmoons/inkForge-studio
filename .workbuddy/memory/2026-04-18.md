## 链接改写步骤条 Bug 修复（两处）

### Bug 1（前端）：面板不刷新
- **根因**：`selectStep` 在 `oldSel === stepNum` 时直接 return，步骤 running→done 时面板不更新
- **修复**：`selectStep` 增加 `forceRefresh` 参数；`handleStepN` 完成时以 `true` 调用
- **改动文件**：`web_static/rewrite.html`

### Bug 2（后端，真正根因）：stepResults 永远为 null
- **根因**：`web_app.py` 的 `on_step` 回调，步骤完成时推送的 `result` 事件 msg 是纯文本字符串（`"   [1/7] 内容抓取完成"`），而非 JSON。前端 `subscribeSSE` 对 `result` 事件做 `JSON.parse(d.msg)`，解析失败 catch 直接 return，`handleStepResult` 从未执行，`stepResults[N]` 永远是 null
- **修复**：`on_step` 步骤完成时改为 `push_log(task_id, json.dumps(step_msg), "result")`，推送含 `step` 字段和完整数据的 JSON
- **改动文件**：`web_app.py`

## 文章时间错误修复（二次迭代）
- **问题1**：AI 把"今天"写成"昨天"（如"就昨天，4月18号"）
- **问题2**：AI 使用了未发生的未来时间（上午生成文章却写"今天下午"）
- **根因**：prompt 只告诉 AI 日期，但没有约束时间表述的准确性
- **修复**（`modules/ai_writer.py` `build_article_prompt()`）：
  - 新增动态时段变量 `_time_context`，根据当前小时自动判断"上午/下午/晚上"
  - 两条 prompt 路径都加上**时间约束规则**：
    - 明确告知 AI 当前是"{日期} {时段}"
    - 禁止使用"今天下午/晚上""刚刚""几小时前""昨天""前天"等无法验证或相对的时间词
    - 只允许用已确定的事实性时间（具体日期、"本周"、"近期"）
