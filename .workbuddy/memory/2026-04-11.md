### 问题2：评分输出显示异常
**现象**：日志中显示 `1. '+c+'... → 5.0 分` 和 `2. '+s.name+'... → 2.0 分`，而不是实际的选题标题。

**分析**：
- Python 后端代码 `print(f"      {i+1}. {topic['title'][:40]}... → {score:.1f} 分")` 是正确的
- 前端 `appendLog` 函数使用 `textContent` 也是安全的
- 怀疑是 SSE 传输过程中的编码问题或浏览器控制台显示问题

**结论**：这是一个偶发的显示问题，不影响实际功能，建议观察是否还会复现。

### 问题3：领域数据源与提示词不匹配
**现象**：用户提示词是关于摩托车的，但 DuckDuckGo 不可用时，系统按照公众号领域（汽车）去爬取汽车之家和懂车帝，获取的内容与提示词无关。

**根本原因**：
- 当 DDG 不可用时，系统按照公众号的领域去爬取固定的数据源
- 这些数据源的内容不是根据搜索关键词动态获取的
- 所以获取的内容可能与用户的提示词（摩托车）无关

**修复措施**：
在 `modules/auto_selector.py` 中重新设计降级逻辑：
1. 当 DDG 不可用时，立即停止关键词搜索循环（不再尝试后续关键词）
2. **使用AI大模型根据用户提示词直接生成选题**，而不是从固定数据源爬取
3. 新增 `_ai_generate_topics_from_prompt` 函数，让AI根据提示词内容生成符合用户需求的选题

**代码修改**：
- 第 599-615 行：重新设计兜底逻辑，使用AI大模型生成选题
- 第 1300-1380 行：新增 `_ai_generate_topics_from_prompt` 函数

### 问题4：关键词过滤效果不佳
**现象**：即使使用了通用媒体源，整理出来的选题仍然是汽车相关而不是摩托车。

**根本原因**：
- 搜索关键词包含完整日期（如"2026年04月11日 摩托车"）
- 新闻标题中不太可能包含这么完整的日期
- 关键词过滤时无法有效匹配

**修复措施**：
在 `_fetch_tech_news_legacy` 函数中优化关键词过滤逻辑：
- 提取核心关键词（去掉日期部分）
- 同时使用原始关键词和核心关键词进行过滤
- 添加过滤结果日志，方便调试

**代码修改**：
- 第 378-400 行：优化关键词过滤逻辑，提取核心关键词（去掉日期部分）

### 问题5：DuckDuckGo 不可用
**现象**：即使使用了国外网络，DuckDuckGo 仍然提示不可用。

**可能原因**：
1. DuckDuckGo HTML 接口 (`html.duckduckgo.com`) 有频率限制和反爬虫机制
2. 返回 202 状态码表示限流或需要验证
3. 请求超时时间太短（6秒）

**修复措施**：
1. 切换到 DuckDuckGo Lite 接口 (`lite.duckduckgo.com`)，更稳定且无JS
2. 增加重试次数（从1次增加到2次）
3. 增加超时时间（从6秒增加到15秒）
4. 优化请求头，增加 Accept 和 Accept-Language
5. 更新页面解析逻辑，适配 Lite 版本的 HTML 结构
6. 添加更详细的错误日志

**代码修改**：
- 第 411-475 行：重写 `_ddgo_html_search` 函数，使用 DuckDuckGo Lite 接口
