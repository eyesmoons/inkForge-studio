# 墨锻工坊（inkForge Studio）

**AI 辅助内容工作台** — 面向内容创作者的下一代 AI 协作写作平台



## 一、项目背景

### 1.1 内容创作的痛点

在自媒体与数字内容爆发式增长的当下，中文内容创作者面临着多重挑战：

- **灵感匮乏**：每日选题耗费大量时间，热点追踪依赖人工多平台切换，效率低下；
- **写作门槛高**：从选题、大纲到正文，全流程依赖个人经验，新手难以快速产出高质量内容；
- **工具碎片化**：选题、写作、排版分散在不同工具之间，缺乏一体化工作流；
- **AI 能力接入难**：大模型厂商众多（DeepSeek、OpenAI、智谱、百度、阿里、字节等），接口各异，中小创作者缺乏统一接入与切换能力；
- **合规风险**：国内对 AI 生成内容有标识要求，创作者需要便捷的工具来满足监管合规。

### 1.2 项目定位

**墨锻工坊（inkForge Studio）** 是一款面向内容创作者的 **AI 辅助协作写作工作台**。它不是简单的"AI 文章生成器"，而是一个覆盖 **灵感发现 → 协同创作 → 资源管理** 全流程的一站式内容生产平台。

项目以"**人机协同、赋能创作**"为核心理念，将 AI 作为创作伙伴而非替代者，帮助创作者把精力聚焦于创意与判断，把重复性、机械性的工作交给 AI。



## 二、技术架构

### 2.1 整体架构概览

墨锻工坊采用 **前后端同栈、轻量部署** 的架构设计，整体分为四层：

```
┌─────────────────────────────────────────────────────────┐
│                    前端展示层 (Presentation)               │
│  原生 HTML / CSS / JavaScript · 无框架依赖 · CSS 变量主题   │
│  页面：协同创作 · 每日热搜 · 历史上的今天 · 素材库 · 历史文章  │
└─────────────────────────────────────────────────────────┘
                              │ HTTP / Server-Sent Events
┌────────────────────────────────────────────────────────┐
│                    接口网关层 (API Gateway)              │
│              Python / Flask · RESTful API               │
│         会话管理 · 用户鉴权 · 路由分发 · 流式日志            │
└─────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────┐
│                    业务模块层 (Business Modules)          │
│  协同创作 · 智能选题 · AI 写作                              │
│  热搜抓取 · 历史上的今天                                    │
│  历史文章 · 关键词提取 · AI 标识                            │
└─────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────┐
│                    数据持久层 (Persistence)               │
│             SQLite · 文件存储                             │
└─────────────────────────────────────────────────────────┘
```

### 2.2 后端：Python / Flask

后端基于 **Flask** 轻量框架，单进程部署、零外部依赖（除 Python 标准库与 SQLite），适合个人创作者与小团队私有化部署。

**核心入口**：`web_app.py`

| 能力模块 | 说明 |
|---------|------|
| 路由体系 | 覆盖页面路由 + REST API + SSE 流式端点 |
| 会话管理 | 基于 Cookie 的 Session 识别，支持注册 / 登录 / 鉴权 |
| 流式日志 | 基于 `Server-Sent Events` 的实时任务日志推送 |
| 多后端 LLM 适配 | 自动检测并切换多种大模型后端 |



### 2.3 前端：原生 HTML / CSS / JS

前端 **无框架依赖**，采用原生 HTML5 + CSS3 + ES6 JavaScript，保证轻量、可移植、易二次开发。

**设计体系**：

- **CSS 自定义属性（CSS Variables）**：通过 `:root` 变量统一管理颜色、间距、圆角、阴影，支持主题切换；
- **亮色主题**：当前默认主题遵循 **WCAG AA 对比度标准**（正常文本 ≥ 4.5:1），兼顾可读性与视觉舒适；
- **组件化 CSS**：`common.css` 提供跨页面共享的卡片、按钮、表单、模态框、状态徽章等组件；
- **响应式布局**：侧边栏 + 主区域的经典工作台布局，支持侧边栏收起。

**主要页面**：

| 页面 | 路径 | 功能 |
|------|------|------|
| 协同创作工作台 | `/collaborative/:id` | 选题 → 大纲 → 内容 三阶段写作 |
| 每日热搜 | `/hotrank.html` | 16 平台热搜聚合 |
| 历史上的今天 | `/today_in_history.html` | 历史事件时间轴 |
| 历史文章 | `/history.html` | 已保存文章的管理与检索 |
| 系统配置 | `/settings.html` | AI 基础配置 + 多模型管理 |

### 2.4 数据存储

采用 **SQLite** 作为主数据库，文件型存储、零配置、便于备份与迁移。

**核心数据表**：

| 表 | 用途 |
|----|------|
| `users` | 用户账号、密码哈希 |
| `accounts` | 创作者账号配置 |
| `ai_models` | 多模型配置（厂商、API Key、Base URL、用途） |
| `collaborative_projects` | 协同创作项目（标题、当前阶段） |
| `article_history` | 历史文章（选题、大纲、正文、字数、时间） |
| `ai_label_config` | AI 标识文案配置 |

文章内容以 **Markdown 文件** 形式存储在本地 `output/articles/` 目录，同时关键元数据入库，兼顾可读性与可检索性。

### 2.5 业务模块全景（14 个模块）

| 模块 | 文件 | 职责 |
|------|------|------|
| AI 写作 | `ai_writer.py` | 接收选题/提示词 → 调用 LLM → 生成大纲 / 正文 / Markdown 文章 |
| AI 标识 | `ai_labeler.py` | 读取 / 附加 / 校验 / 修改文章末尾 AI 标识文案，满足合规要求 |
| 历史文章 | `article_history.py` | 保存 / 列表 / 获取 / 更新 / 删除，集成 AI 标识自动追加 |
| 每日热搜 | `hotrank.py` | 抓取 16 个平台热搜榜（B站、微博、知乎、百度、抖音、36氪等） |
| 历史上的今天 | `today_in_history.py` | 抓取历史上的今天数据，按事件类型分类 |
| 用户数据库 | `user_db.py` | SQLite 连接管理、事务封装、表结构初始化 |

## 三、应用场景

### 3.1 个人自媒体创作者

**场景**：一位科技类自媒体作者，每天需要产出 1-2 篇高质量文章。

**工作流**：

1. **灵感发现**：打开「每日热搜」查看 16 平台实时热榜，或浏览「历史上的今天」寻找纪念日选题；
2. **协同创作**：进入工作台，输入想法 → AI 生成 3-5 个候选选题 → 选择 / 自定义选题 → AI 生成大纲 → 编辑大纲 → AI 生成正文；
3. **润色排版**：使用「AI 助手」润色段落，切换排版风格（舒展 / 紧凑 / 正式 / 古典）实时预览；
4. **合规校验**：文章保存时自动附加 AI 标识；
6. **归档复用**：文章进入「历史文章」，支持搜索、查看、继续编辑。

### 3.2 内容营销团队

**场景**：企业市场部需要批量产出产品软文、活动推文、品牌故事。

**工作流**：

1. **多模型协同**：在「系统配置」中配置多个模型（DeepSeek 用于对话、GPT-4 用于英文、智谱用于长文本），按用途灵活切换；
4. **账号配置**：为不同平台（公众号、知乎、头条）配置独立的笔名、文风、字数、主题提示词，创作时自动应用。

### 3.3 教育与知识工作者

**场景**：教师、知识博主、技术作者需要撰写教程、课程、技术文档。

**工作流**：

1. **结构化写作**：利用「选题 → 大纲 → 内容」三阶段工作流，先确立清晰框架，再逐步填充内容；
2. **大纲导航**：内容阶段采用 Word 式导航窗格，左侧大纲、右侧正文，点击大纲快速定位；
3. **排版风格**：技术文档选择「正式」风格（宋体 + 两端对齐），文学内容选择「古典」风格（楷体 + 暖色调）；
4. **版本管理**：教程迭代时通过版本快照追踪每次修改，对比差异、回滚到历史版本。



## 四、创新点

### 4.1 三阶段协同创作工作流（Topic → Outline → Content）

区别于市面上"一键生成全文"的粗放模式，墨锻工坊设计了 **选题 → 大纲 → 内容** 三阶段渐进式工作流：

- **选题阶段**：AI 根据用户想法生成 3-5 个候选选题，用户可选择或自定义，避免"AI 自说自话"；
- **大纲阶段**：AI 生成结构化大纲，用户可自由编辑调整，确保内容框架符合预期；
- **内容阶段**：基于确认后的大纲逐段生成正文，左侧大纲导航、右侧编辑，支持实时排版预览。

**创新价值**：将 AI 从"黑盒生成器"变为"可干预、可引导的创作伙伴"，兼顾效率与可控性。

### 4.2 多模型统一管理与智能切换

系统支持 **9 大厂商** 的大模型（OpenAI、DeepSeek、Anthropic、Google、智谱、百度、阿里、字节、自定义），并提供：

- **多模型管理**：在「系统配置」中配置多个模型，分别用于对话、长文本、图像生成等不同用途；
- **默认模型**：设置默认模型后，新建创作自动优先使用；
- **智能 fallback**：5 级后端自动选择（数据库模型 → config.json → 环境变量 → 本地 Ollama → 内置模板），确保任何环境下都能产出内容。

**创新价值**：创作者不再被单一厂商锁定，可根据成本、效果、可用能力灵活选择，且完全兼容私有化部署的本地模型。

### 4.6 AI 标识合规体系

构建了完整的 AI 生成内容标识体系：

- **自动附加**：文章保存 / 更新时自动在末尾追加 AI 标识文案；
- **标识校验**：检测文章是否已包含标识，避免重复或遗漏；
- **可配置**：支持自定义标识文案，适配不同平台要求；
- **默认兜底**：未配置时使用默认标识"本文由 AI 辅助生成，请仔细甄别文章内容"。

**创新价值**：在 AI 内容监管趋严的背景下，帮助创作者便捷满足合规要求，降低法律风险。

### 4.7 灵感发现的双引擎：热搜 + 历史

- **每日热搜**：聚合 16 个主流平台（B站、微博、知乎、百度、抖音、豆瓣、IT之家、少数派、澎湃新闻、今日头条、36氪、稀土掘金、腾讯新闻、网易新闻）的实时热搜，一站式热点追踪；
- **历史上的今天**：抓取历史事件、人物出生/逝世、战争政治、科技文化等分类事件，为纪念日选题提供素材。

**创新价值**：将"被动找选题"变为"主动发现选题"，解决创作者最大的灵感痛点。

### 4.8 零依赖、可私有化部署

- **后端**：仅依赖 Python 标准库 + Flask + SQLite，无重型中间件；
- **前端**：原生 HTML / CSS / JS，无构建步骤、无 npm 依赖；
- **存储**：SQLite 单文件数据库 + 本地 Markdown 文件，备份迁移只需复制文件夹；
- **部署**：单进程启动，支持本地、服务器、Docker 等多种部署方式；
- **离线可用**：内置本地 Ollama 支持 + 模板 fallback，无网络时仍可产出内容。

**创新价值**：数据完全自主可控，适合对数据安全、隐私合规有要求的创作者与团队。
